# Demo UI guidelines

Rules for every UI generated by `oci-agent-ui` (Spec 018). The page is for the
**customer persona** of the agent specification, not for the developer.

## End-user rules

**E1. Business language.** Titles, labels, help texts, and messages use the
persona's vocabulary and the specification's language. API field names never
appear on the page.

| Avoid | Prefer |
| --- | --- |
| `quantity` | "How many pieces" |
| `available_quantity` | "In stock" |
| `order_id` | "Order number" |
| `status: rejected` | "We cannot complete this order" |

**E2. What matters to the persona.** Organize the page around the use case and
the expected outcomes of the business context. The outcome is the most visible
element of the result; show only the fields that serve it.

**E3. No technical data by default.** No raw JSON, HTTP status codes, latency,
OCIDs, request identifiers, model names, or stack traces. Business identifiers
(an order number, a ticket number) are business data: show them.

**E4. Errors in plain words.** A rejected request explains why and what the
user can do; prefer the agent's own business message when its response has
one. An unavailable agent shows only "the service is temporarily
unavailable". Technical causes go to the server log.

**E5. Ready to demo.** Offer two or three example requests from the use case,
each with a short label, so a presenter can show the agent in one click.

**E6. Explicit exceptions only.** Set `technicalView: true` (a collapsed
"Technical details" panel) only when the developer asks for it explicitly.

## Template rules

**T1. Configuration first.** Generate `app/demo-config.js` from the approved
UI specification; the template page renders it. Add a component only when the
configuration cannot express the result (for example several cards of
offers), and keep it business-only.

**T2. Never change the bridge.** Keep `app/api/agent/route.js` as in the
template: the browser calls only `/api/agent`; the route reads
`AGENT_BASE_URL` and `AGENT_PATH` from `.env.local`; 400 and 422 are business
rejections; any other failure is "unavailable" and is logged.

**T3. No address or secret in the code.** The agent address lives only in
`ui/.env.local`. Never write an OCID, an endpoint, a key, or a token in any
generated file.

**T4. Local only.** Keep `--hostname 127.0.0.1` in the `package.json`
scripts.

**T5. Next.js 16.** Before writing code beyond `demo-config.js`, read the
documentation shipped in `ui/node_modules/next/dist/docs/` after `npm
install`: its APIs differ from older versions.
